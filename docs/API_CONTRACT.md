# PurposeFit API contract

For the front-end agent and for whoever builds `api/main.py` in Phase 9. The JSON below is taken from the real stage files in `runs/<run_id>/` and from the pets-eval scorecard. The same shapes are in `web/fixtures/`, generated by `scripts/export_ui_fixtures.py`. If this file and a fixture disagree, the fixture wins; report the gap.

## 0. What is real and what is a placeholder

| Part | Status |
| --- | --- |
| Manifest, labels, findings, plan, transform stats, pets-eval scorecard, leaderboard rows | Real. Produced by the pipeline today. |
| Scenario list with utility tasks | Real. Read from the public `scenarios.json` and the pets-eval task registry. |
| `gate`, `residual_risks`, `k` summary | Shape fixed here. The pipeline does not produce them yet. The gate is produced by `verify.build_gate` with the rule in section 4.5 (thresholds in `api/pipeline/config.py`). Fixtures are exported from the real scorecards. |
| `ablation` | Real for the rule layers, train split only, from `tests/redact_eval.py`. Produced by the pipeline in Phase 7. `[]` for CS-S3. |
| `spans`, `per_label` in the redact stage | Real since Phase 5 for CS-S1 (rule layers 1 to 4). `surrogate_text` stays `null`: typed placeholders only. |
| `policy_card` in the report stage | Shape not fixed yet. `null` until Phase 8. |

## 1. Conventions

- Base path `/api`. All bodies are JSON (`application/json; charset=utf-8`) except the export download.
- Ids: `run_id` matches `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$`. Scenario ids look like `CS-S1`.
- Missing values are `null`, never an empty string or `0`. A utility score of `null` means "not answerable": show the words, not 0.
- Rates and scores are numbers between 0 and 1. Counts are integers. Times are ISO 8601 UTC strings. Durations are milliseconds.
- Responses never contain cell values from the original data, keys, row maps or server file paths. The one exception is the redact stage, which carries the synthetic transcript turns the Text screen shows.
- Errors, for any endpoint:

```json
{"error": {"code": "run_not_found", "message": "No run with id p9-xyz."}}
```

| HTTP | `code` | When |
| --- | --- | --- |
| 400 | `bad_request` | Body fails validation (unknown scenario, unsafe run id, bad stage name). |
| 404 | `run_not_found`, `stage_not_found` | Unknown run, or stage not written yet. |
| 409 | `gate_failed` | Export asked for while the release gate has not passed. |
| 413 | `upload_too_large` | CSV upload over 50 MB. |
| 503 | `not_ready` | Server is up but the proving ground data is missing. |

## 2. Endpoints

### GET /api/health

```json
{"status": "ok", "git_hash": "8c60fac", "key_id": "39ffd61450cc",
 "llm": {"provider": "none", "model": "none", "enabled": false},
 "proving_ground": true}
```

`key_id` is a one-way public id of the HMAC key (12 hex characters). The key itself is never returned. The server refuses to start without the key, so `status` is `ok` whenever the endpoint answers.

### POST /api/runs

Request, JSON:

```json
{"dataset": "customer_service", "scenario_id": "CS-S1", "no_llm": true}
```

or `multipart/form-data` with fields `scenario_id`, `no_llm` and a `file` (one CSV, at most 50 MB) instead of `dataset`. `no_llm` defaults to `false`. Response `202`:

```json
{"run_id": "r-20261108-0001", "status": "queued"}
```

The pipeline runs in a background task. Poll `GET /api/runs/{id}`.

    {"stage": "transform", "status": "done", "duration_ms": 942},

- `status`: `queued`, `running`, `done` or `failed`. `done` does not mean the gate passed.

Fixtures: `run.CS-S1.json`, `run.CS-S3.json`.

### GET /api/runs/{id}/stages/{stage}

`stage` is one of `profile`, `detect`, `plan`, `transform`, `redact`, `verify`, `report`. A stage that has not run returns 404 `stage_not_found`. The payload differs per stage:

| Stage | Payload | Fixture |
| --- | --- | --- |
| `profile` | array of `ColumnProfile` | `stage.profile.json` |
| `detect` | `{dataset, labels, findings, stats}` | `stage.detect.json` |
| `plan` | `PolicyPlan` | `plan.CS-S1.json`, `plan.CS-S3.json` |
| `transform` | transform stats | `stage.transform.CS-S1.json`, `.CS-S3.json` |
| `redact` | `{..., turns, per_label}` (section 4.6) | `stage.redact.CS-S1.json`, `.CS-S3.json` |
| `verify` | `{scenario_id, ours, baseline, baseline_name, gate, k, residual_risks, ablation}` | `stage.verify.CS-S1.json`, `.CS-S3.json` |
| `report` | `{plan_table_md, policy_card}` | `stage.report.CS-S1.json`, `.CS-S3.json` |

### GET /api/runs/{id}/export

Returns `application/zip`, `Content-Disposition: attachment; filename="<run_id>_release.zip"`. The zip holds the released tables as CSV, `policy_card.json` and `07_plan_table.md`. It never holds row maps, gazetteer values or keys. `policy_card.json` is added in Phase 8; until then the zip has the tables and the plan table only. Returns 409 `gate_failed` while the gate has not passed; the error `message` names the blocking checks.

## 3. Reading the plan

`PolicyPlan` (stage `plan`, also the `03_plan.json` file):

```json
{
  "dataset": "customer_service",
  "scenario_id": "CS-S3",
  "released_tables": ["conversations"],
  "policies": [FieldPolicy, ...],
  "k": 751,
  "key_id": "39ffd61450cc"
}
```

`k` is the smallest k over released tables with kept quasi-identifiers (1 before transform; stays 1 when none are kept). `policies` has one entry per column of every table of the dataset, in table then column order, followed by one `suppress_k` entry per released table that keeps quasi-identifiers.

`FieldPolicy`:

```json
{"table": "conversations", "column": "language", "action": "keep",
 "params": {"role": "quasi_identifier", "subtype": "LANGUAGE", "tasks": ["CS-U6"],
            "level": "exact", "fallback_level": "exact", "ladder": ["exact"],
            "quasi_identifier": true},
 "reason": "used by CS-U6; one level only for this subtype, kept exact",
 "guarantee": "released as is"}
```

| `action` | Meaning | `guarantee` text |
| --- | --- | --- |
| `keep` | Released as is. | released as is |
| `drop` | Column not released. | not released |
| `withhold_table` | Whole table not released: not needed for this purpose. | not released |
| `hmac` | Keyed pseudonym (HMAC-SHA256). | keyed pseudonym (HMAC-SHA256); still personal data |
| `generalise` | Coarsened to `params.level`. | coarsened to a fixed level; checked for k >= 5 |
| `redact` | Free text kept for a task; identifiers removed by the text redactor (Phase 5). | free text; identifiers replaced by typed placeholders (rule redactor); leakage measured by pets-eval |
| `suppress_k` | Table-level entry with `column: "*"`: the k check. | k-anonymity on the kept quasi-identifiers |

Every `params` except the one on `suppress_k` has `role` (a privacy role) and `subtype` (a taxonomy subtype). Optional keys:

| Key | On | Meaning |
| --- | --- | --- |
| `tasks` | keep, hmac, generalise, redact | Utility task ids that use the column. |
| `gazetteer` | drop, withhold_table | `true` for a direct identifier whose values go to the redactor. Values are never in the API. |
| `level`, `fallback_level`, `ladder`, `quasi_identifier` | kept quasi-identifiers | Chosen level, the fixed B2 level, the levels tried (finest first). Show `level` in the Plan table. |

`suppress_k` entry, after transform:

```json
{"table": "conversations", "column": "*", "action": "suppress_k",
 "params": {"qis": ["language"], "k_target": 5, "max_row_suppression": 0.02,
            "k": 751, "k_pycanon": 751, "rows_suppressed": 0, "row_budget": 238,
            "cells_blanked": {}, "method": "level search",
            "search": {"tried": 1, "qualifying": 1, "scored": 1, "row_budget": 238,
                       "chosen": {"levels": {"language": "exact"}, "utility": 1.0, "rows_suppressed": 0},
                       "runner_up": null}},
 "reason": "k >= 5 on the kept quasi-identifiers only",
 "guarantee": "k-anonymity on the kept quasi-identifiers"}
```

`method` is `"level search"` or `"fallback: fixed B2 levels and cell blanking"`. `runner_up` is `null` when only one combination qualified. This entry has no `role` or `subtype`. Roles come from the vocabulary in `vendor/proving_ground/metadata/taxonomy.md`: `direct_identifier`, `quasi_identifier`, `sensitive_attribute`, `technical_identifier`, `free_text`, `record_key`, `non_sensitive`.

Plans for CS-S1 and CS-S3 differ in which tables are released (`conversations` and `turns` against `conversations` only) and in which columns are kept, so the Compare view is a join of the two `policies` arrays on `(table, column)`.

## 4. Other shapes

### 4.1 FieldLabel (stage `detect`, `labels`)

```json
{"dataset": "customer_service", "table": "conversations", "column": "handle_time_s",
 "privacy_role": "non_sensitive", "subtype": "DURATION", "confidence": 0.7,
 "reason": "numeric values and column name has 'time', a duration [name_duration]",
 "source": "rule"}
```

`source` is `rule`, `llm` or `manual`. `confidence` is between 0 and 1. `reason` ends with the rule family in square brackets.

### 4.2 Findings (stage `detect`, `findings`; fixture `findings.json`)

A list; empty when nothing was found. Findings name tables and columns only, never values. Two kinds exist:

```json
{"kind": "unkeyed_hash", "dataset": "unseen", "table": "export_2025_q4", "column": "c20",
 "source_column": "c05", "algorithm": "SHA-256", "variant": "canonical_hetu",
 "match_rate": 1.0, "source_role": "direct_identifier"}
```

```json
{"kind": "dependency", "dataset": "health", "table": "ed_visits", "column": "los_minutes",
 "source_column": "heart_rate", "agreement": 0.97}
```

`unkeyed_hash`: `column` is an unkeyed hash of `source_column`, so it can be reversed by enumeration. `algorithm` is `MD5`, `SHA-1` or `SHA-256`. `variant` says how the source was spelled before hashing (`trimmed`, `upper`, `lower`, `canonical_hetu`, `canonical_hetu_lower`, `canonical_iban`, `canonical_iban_lower`). `dependency`: `column` is numeric and is zero or empty exactly where the sensitive column `source_column` is empty, in `agreement` of the rows. The `customer_service` dataset has no findings today, so `stage.detect.json` has `findings: []`. `findings.json` holds the three real findings from other datasets so the panel can be built; the front end writes its own sentence from the fields.

Notes for the UI:
- `tables.<name>.status` is `released`, `withheld` or `error`. A withheld table has only `table`, `status`, `rows_original`. An `error` table has `error` (one sentence; the server removes the stack trace) instead of metrics.
- `k_anonymity` is either `{qis, n, n_classes, min_k, median_k, share_below: {"k<2", "k<5", "k<10"}, sample_uniqueness}` or `{note}`. All are optional: test for the key.
- `free_text.<column>` is either the full evaluation above or `{evaluated, status: "withheld", identifying_leakage_rate}` for a withheld column.
- `risks` and `risk_components` map a name to a number or `null`. The keys of `risk_components` are `"<table>: <risk name>"` and differ between ours and the baseline (the baseline releases `customers`). Join on the key and show a dash where one side is missing.
- `utility` has one entry per task of the scenario. `required` is `true` for the scenario's own tasks. `score` is `null` with `metric: "not answerable"` when columns the task needs were removed.
- `summary.privacy`, `utility` and `composite` are the headline numbers. They carry the `label` above.

```json

 "checks": [
   {"id": "direct_identifiers", "name": "Residual direct identifiers", "kind": "direct_identifiers",

    "reason": "No direct identifier is retained in any released table.", "source": "pets-eval"},
   {"id": "k_anonymity", "name": "k-anonymity", "kind": "k", "status": "pass", "value": 751,
    "threshold": 5, "comparison": "at_least",
    "reason": "pyCANON finds k = 751 on the released quasi-identifiers.", "source": "pyCANON"},
   {"id": "risk_vs_baseline", "name": "Risk components against B2-k", "kind": "baseline",
    "status": "fail", "value": 1, "threshold": 0, "comparison": "at_most",
    "reason": "Not lower than B2-k: turns: free-text identifier leakage.", "source": "pets-eval",
    "details": [{"name": "turns: free-text identifier leakage", "ours": 1.0, "baseline": 0.8012, "ok": false}]},
   {"id": "text_leakage", "name": "Identifying leakage in free text", "kind": "text",
    "status": "fail", "value": 1.0, "threshold": 0.1, "comparison": "at_most",
    "reason": "Identifying leakage is 1.000 in turns.text, above the limit of 0.10.", "source": "pets-eval"}
 ]}
```

Always exactly four checks, in this order, ids fixed: `direct_identifiers` (every "direct identifiers retained" component is 0), `k_anonymity` (pyCANON k at least 5 for every released table with quasi-identifiers; passes with `value: null` when none is released), `risk_vs_baseline` (every risk component that ours and B2-k both measure is lower than B2-k's, or both are 0; `value` is the number of components that are not; `details` lists each compared component; fails when no B2-k scorecard exists) and `text_leakage` (identifying leakage of every released free-text column at most 0.10; `value` is the worst rate, `null` when no text column is released). `reason` is a plain sentence written by the server, shown as is. `passed` is `true` when `blocking` is empty. `status` is `pass` or `fail`. `comparison` is `at_most`, `at_least`. Show a failed gate as an error notification that names the checks in `blocking`. The gate is also written to `06_gate.json`.

**KSummary**: `{"table": "conversations", "qis": ["language"], "pipeline_k": 751, "pycanon_k": 751, "method": "level search"}`. The list is empty when no quasi-identifier is kept. Show `pycanon_k` next to `pipeline_k`.

**ResidualRisk**: `{"id": "k_scope", "text": "k-anonymity limits singling out on the stated quasi-identifiers only; it does not stop attribute inference inside a uniform group.", "source": "docs/FACTS.md"}`. Plain sentences for a list. The text is written by the server.

**Ablation**: a row per redactor layer switched off, measured on the customer_service train split (not the full release).

{"layer_off": "controller", "leakage": 0.2578, "precision": 0.98, "utility": null, "n_spans": 34064,
 "scope": "customer_service train split"}

`layer_off` is one of `patterns`, `normalise`, `controller`, `dvv`, `cues` (the gazetteer is two sources, reported separately; `ner` and `health` come in Phase 6). `leakage` is the identifying leakage rate of the free text and `precision` the label-agnostic span precision, both between 0 and 1. `utility` is `null` until Phase 7. ### 4.6 Redact stage (Text screen; fixtures `stage.redact.CS-S1.json`)

```json
{
  "dataset": "customer_service", "table": "turns", "column": "text",
  "redacted": true, "layers_run": ["patterns", "normalise", "controller", "dvv", "cues"], "n_turns": 20,
  "turns": [
    {"record_id": "T0000001", "conversation_id": "e814fabe647694efd49d",
     "original_text": "aallokko kundtjänst ...", "protected_text": "aallokko kundtjänst ...",
     "surrogate_text": null,
     "spans": [{"start": 21, "end": 27, "label": "PERSON", "layer": "gazetteer", "score": 0.9}]}
  ],
  "per_label": [{"label": "NATIONAL_ID", "n": 5120, "leaked": 80, "rate": 0.0156}],
  "span_labels_note": "rule layers only; NER and health layers are not run yet"
}
```

- For CS-S1 `redacted` is `true`, `layers_run` lists the layers that ran (`patterns`, `normalise`, `controller`, `dvv`, `cues`; the gazetteer spans all carry `layer: "gazetteer"` or `"normalise"` and the span file also records which source found them), every `spans` holds the turn's spans and `per_label` is the pets-eval leakage per gold label over the whole release (`leaked` counts values still recoverable; `LOCATION`, `DATE`, `ORG` and `HEALTH` are not redacted by the rule layers, so their rates stay high). The fixture turns are the first 20 of the synthetic `customer_service` turns. Treat the span shape above as fixed: it is the `Span` contract without `record_id`.
- `start` and `end` are character offsets into `original_text` (0-based, end exclusive). `label` is one of `PERSON`, `NATIONAL_ID`, `EMAIL`, `PHONE`, `ADDRESS`, `LOCATION`, `DATE`, `AGE`, `IBAN`, `PAYMENT_CARD`, `ACCOUNT_NUMBER`, `IP_ADDRESS`, `LICENSE_PLATE`, `ORG`, `URL`, `USERNAME`, `SECRET`, `HEALTH`, `DEVICE_ID`, `PROPERTY_ID`. `layer` is one of `patterns`, `normalise`, `gazetteer`, `cues`, `ner`, `health`. `score` is between 0 and 1.
- `protected_text` shows typed placeholders such as `[PERSON]`. `surrogate_text` is the consistent-surrogate version, or `null` when the run has none. Enable the Toggle only when `surrogate_text` is not `null`.
- For a scenario that withholds the transcripts (CS-S3), `turns` is `[]` and `table` is `null`. Show a "withheld: not needed for this purpose" notice.
- `conversation_id` is the keyed pseudonym of the release, not the original id. `turn_id` is released unchanged (see the limitation in `docs/reports/phase3_plan.md`).
- The turn text is synthetic data (CC BY 4.0, Since AI ry). Do not log it.

### 4.7 Report stage

`{"plan_table_md": "| Table | Column | Role | Action | Level | Reason |\n...", "policy_card": null}`. `plan_table_md` is the field-by-field plan as a Markdown table, followed by one k check line per table and, when a level search ran, one summary line of the search. `policy_card` is `null` until Phase 8. The Export screen should offer it only when it is not `null`.

### 4.8 Leaderboard rows (fixture `leaderboard.json`)

Not an endpoint in the list above; the server may add `GET /api/leaderboard` returning this array, or embed it in a later response. The shape:

```json
{"created_utc": "2026-11-07T23:31:38+00:00", "run_id": "p4-CS-S1", "git_hash": "9a5f9c6",
 "dataset": "customer_service", "scenario": "CS-S1", "method": "purposefit",
 "privacy": 0.375, "utility": 1.0, "composite": 0.5238,
 "worst_risk": 1.0, "worst_risk_component": "turns: free-text identifier leakage",
 "k": null, "k_pycanon": null,
 "utility_tasks": {"CS-U1": 1.0, "CS-U3": 1.0, "CS-U4": 1.0, "CS-U5": 1.0},
 "note": "phase 4 search; structured only; text raw; rules-only labels"}
```

`method` is `purposefit` or `B2-k (rerun)`. `utility_tasks` maps a task id to a score or `null` (not answerable). `worst_risk_component` is `null` when every risk is 0. Rows are in the order they were logged and include earlier runs of the same scenario (for example `p3-CS-S1`, before the level search); group by `scenario` and `method` and take the latest `created_utc` for headline tiles.

## 5. Not in this contract

- Authentication. The demo runs locally.
- Streaming progress. Poll `GET /api/runs/{id}` about once a second while `status` is `queued` or `running`.
- Writing: the UI never edits a plan. A changed scenario is a new run.
